Design decisions

ISA

  • Two-operand registers

    The formats only have room for two register fields, so rt/rd is both a source and the destination. rs always drives read port 1 and ALU input A; rt/rd drives read port 2 and the write port. That one wiring serves every format: rs is the base for lw and sw, and rt/rd is the data for sw.

    Trade-offR-type overwrites one of its inputs, and operand order is fixed: sub gives rs − rd. To keep a value, copy it first.

  • Funct code is the ALU code

    The ALU's op numbering matches the spec's funct codes (add 0000, sub 0001, sll 0010, and 0011), so control hands funct straight to AluCtrl with no translation table.

    BonusEvery other ALU op is reachable as an R-type too. slt, xor, srl, sra and or work without any change to control.

  • Word addressing

    Memory is addressed in 16-bit words, not bytes. The PC counts instructions (PC + 1) and every load or store moves one full word.

    Trade-offNo byte or character storage. In return, the byte lanes, misalignment checks and load sign-extension of the RV32I core all disappear.

  • Two readings of the 4-bit immediate

    addi, lw and sw zero-extend it in the decoder (0 to 15). Branches sign-extend it in the branch adder (−8 to +7, counted from the branch itself), so loops can jump backwards.

    Trade-offaddi can't load a negative constant (use sub against a register), and a branch reaches at most 8 instructions back or 7 forward. Longer jumps go through jmp.

  • jmp is absolute and doesn't link

    The J-type's 12-bit address goes straight into the PC as {4'b0, addr}. There's no rd field, so nothing is written back.

    Trade-offNo subroutine call or return yet, because there's no jal or jump-to-register.

  • Only the required immediates

    Nine opcodes (0111 to 1111) stay free. An immediate form of every ALU op (opcode 1xxx = R-type op 0xxx using imm) fits in that space, but it was left out because only the 10 required instructions are graded.

    Room to growFree opcodes decode to all-zero control, so adding one later doesn't disturb anything that exists.

Datapath

  • Single-cycle, 16 bits wide, separate memories

    Every instruction finishes in one clock. PC, registers, ALU and both memories are 16 bits wide. Instructions and data live in separate 128 × 16 memories (Harvard), so fetch and a load never compete.

    Trade-offThe clock period is set by the slowest path: lw goes ROM → decoder → registers → ALU → data memory → write-back. Addresses above 127 wrap.

  • The ALU does the branch compare

    cmp.sv was dropped. beq and bne run SUB through the ALU and test zero_loc, which is all an equality check needs.

    Trade-offThe ALU is busy during a branch, so the target needs its own adder (PC + sext(imm)). This is the reverse of the RV32I core, where a comparator did the test and the ALU computed the target.

  • One opcode bit picks branch polarity

    beq (0100) and bne (0101) set identical control signals. take_loc = Branch & (zero ^ opcode[0]) flips the test on the low bit, the same trick RISC-V plays with funct3[0].

    Trade-offtop.sv reads an opcode bit directly, so beq and bne can't swap opcodes without changing that line.

  • Decoder sorts by opcode

    Opcode 0000 is R-type, 0110 is J-type, and everything else is I-type (t = |opcode splits R from the rest). Fields a format doesn't use are driven to 0.

    Why zerosjmp's rd comes out as r0, so even a stray write would land on the register that ignores writes.

  • Control is pure decode

    Control sees only opcode and funct, never data. The branch decision happens in the datapath, in take_loc. Unused opcodes produce all-zero control and behave as no-ops.

    WhyThe same rule as the RV32I core. Control signals depend only on the instruction, which keeps them easy to pipeline later.

  • r0 is zero because writes are blocked

    The register file ignores any write with rd = 0, and reset clears it. No read-side mux is needed.

    Trade-offr0 is only zero after reset. Before reset, every register reads as x in simulation.

  • Spare paths kept for later

    The AluSrcA mux can still steer PC into ALU input A, and the write-back mux still has a PC + 1 input. No current instruction uses either.

    Room to growA jal or a PC-relative add only needs new control rows, not new wiring.

  • Debug ports and halt

    dbg_pc, dbg_instr, dbg_reg_we, dbg_rd and dbg_wb_data give a testbench everything it needs for a commit log. halt goes high when next PC equals PC, a jump to itself.

    Watch outhalt is combinational and flickers for an instant whenever the PC changes. Sample it on a clock edge, not with wait(halt).

AluSrcA is 0 for every opcode, so ALU input A is always R[rs]. MemRead is driven but data memory has no read-enable port; reads are always on. An unused opcode writes nothing and falls through to PC + 1, so it behaves as a no-op.

Glue logic in top.sv

Everything outside the seven instances is these assigns. Each one is a mux, adder or gate in the drawing above.

assign pc_en_loc=1'b1;
assign PC_plus1_loc=PC_loc+16'd1;
assign OpA_loc=AluSrcA_loc?PC_loc:rd1_loc;
assign OpB_loc=AluSrc_loc?imm_loc:rd2_loc;
assign zero_loc=(res_loc==16'd0);
assign take_loc=Branch_loc&(zero_loc^opcode_loc[0]);     //BEQ=0100 BNE=0101, opcode[0] flips the condition
assign br_tgt_loc=PC_loc+{{12{imm_loc[3]}},imm_loc[3:0]};  //ALU is busy comparing, so branches get their own adder
assign next_PC_loc=Jump_loc?{4'b0,jal_addr_loc}:take_loc?br_tgt_loc:PC_plus1_loc;
assign addr_loc=res_loc;
assign dat_loc=rd2_loc;
assign wd_loc=MemToReg_loc?mem_dat_loc:Jump_loc?PC_plus1_loc:res_loc;

assign halt=(next_PC_loc==PC_loc);      //jump-to-self
